## 二、建议的试用顺序（约 10 分钟）

1. **打开页面 1**，先点示例问题「中小企业参与政府采购，预留份额比例是多少？」
   - 看：回答是否先结论后依据、是否带 `[n]` 引用、下方引用卡片是否与回答对应
2. **试一个库外问题**（页面里的「广东省对专精特新企业奖励多少钱？」）
   - 看：是否明确"没有查到"、耗时是否明显更短（闸门直接拒答，约 1 秒）
3. **打开页面 4（Grafana）**，把时间范围选「最近 15 分钟」
   - 看：QPS/延迟/拒答率随刚才提问变化；「服务存活」三个 target 是否 UP
4. **打开页面 6（预警 API）**，刷新看是否有告警记录（含 LLM 归因）
   - 想主动触发：连续问 6 个库外问题（样本量 ≥5 且拒答率高），等 1~2 分钟会出现 `high_refusal_rate` 告警
5. **打开页面 2（Dify）**，点右上「预览」，问同一个问题
   - 看：Dify 侧同样返回引用（retriever_resources），用于对比"平台方案 vs 自研方案"
6. **打开页面 3（RAGFlow）**，进知识库 → 命中测试，输入问题看召回分块
7. **打开页面 5（Prometheus）**，执行：
   ```promql
   fiscal_qa_requests_total
   sum(rate(fiscal_qa_latency_ms_total[5m])) / clamp_min(sum(rate(fiscal_qa_requests_total[5m])),0.0001)
   ```

## 三、试用时值得注意的设计点（面试可讲）

| 观察到的现象 | 背后的设计 |
|---|---|
| 每答都有"耗时 / 检索命中 / 最高相似度" | 指标埋点在 `finally` 里，拒答与异常也计入；`/metrics` 供 Prometheus 抓取 |
| 库外问题 1 秒内拒答 | 相似度闸门 `MIN_SIM_TO_ANSWER=0.33`（阈值可在环境变量调） |
| 有时回答没有引用卡片 | 引用强制：模型没标 `[n]` 时不伪造来源，只展示"模型实际看到的检索片段" |
| 回答里的数字都能在引用原文里找到 | 提示词硬约束 + 评测层数字硬校验（区间要求两个端点都出现） |
| 页面无登录 | 本地演示默认只监听 127.0.0.1；容器/K8s 部署才绑 0.0.0.0（生产需加鉴权网关） |

## 四、常见问题

- **页面 1 打不开**：`Start-Process python -ArgumentList 'serving\qa_service.py','--port','8901'`（日志在 `logs/qa.log`）
- **回答很慢（>30s）**：本地 deepseek-r1:7b 走 CPU 推理，属正常；首问还要加载模型
- **RAGFlow 登录失败**：账号已重置为 `fiscal@local.dev / Fiscal@2026`；若仍失败可在容器里重置：
  `docker exec fiscal-ragflow-ragflow-cpu-1 flask reset-password`（交互式）
- **Grafana 面板无数据**：确认 Prometheus target 是否 UP（页面 5 的 `/targets`）
